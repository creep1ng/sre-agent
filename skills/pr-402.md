## Findings

### P1 — Keep status mutation and terminal audit in the same transaction

[src/sre_agent/control/service.py:2983–2999](https://github.com/creep1ng/sre-agent/blob/ed0622cade395d538efc04d8f23c4b13e04e4c46/src/sre_agent/control/service.py#L2983-L2999)

The transaction at lines 2950–2956 commits before _finish, which receives no audit_session. With a controlled audit-store append failure, PUT returns 503 but SQL status changes from published to inactive, no catalog.status.replace event exists, and retrying the original timestamp returns 409. This is a persisted unaudited lifecycle transition, not a hypothetical race. Append the terminal audit inside the same database transaction and roll back on audit failure. Existing P1 remains valid.

### P2 — Check absent repository result before tuple unpacking

[src/sre_agent/control/service.py:2950–2956](https://github.com/creep1ng/sre-agent/blob/ed0622cade395d538efc04d8f23c4b13e04e4c46/src/sre_agent/control/service.py#L2950-L2956)

Authenticated PUT /v1/skills/audit-missing-version/1.0.0/status returns 500, not the declared audited 404. Store the result, check None, then unpack. Existing finding remains valid.
