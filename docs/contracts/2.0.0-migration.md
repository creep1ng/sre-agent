# Contract 2.0.0 migration

The 2.0.0 package preserves the `/v1` API path and leaves the immutable 1.4.0
snapshot unchanged. Consumers of `PUT /v1/principals/{id}/status` must send the
closed request body below and replace their cached timestamp after every success:

```json
{"status":"inactive","expected_updated_at":"2026-09-07T00:00:00Z"}
```

A missing timestamp is rejected with `422 validation_error`. A stale timestamp
returns `409 status_conflict` without changing the stored principal.

Credential rotation now returns a `CredentialRotation` wrapper on `201`, including
a secret only on the first successful issuance. Its `409` response is a union of
the typed zero-transition failure wrapper (`credential_inactive` or
`rotation_failed`) and the ordinary idempotency conflict error envelope. Standalone
credential issuance dependency failures return the sanitized, retryable `500
credential_issuance_failed` error envelope; no exception or secret detail is
exposed. Administrative hidden-read denials remain public `404`s while their audit
evidence records the private authorization cause. An inactive principal is denied
by the authorization engine; it is not reported as credential authentication
failure. Generic `ActiveInactiveStatus` remains unchanged for other status routes.
