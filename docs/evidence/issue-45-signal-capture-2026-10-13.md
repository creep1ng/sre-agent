# Issue #45: gateway signal-capture slice

**Evidence kind: controlled integration.** This PR adds only the capture half
of CA8. It does not validate chronology, run two real fail/reset cycles, or
claim live Grafana MCP acceptance. The separate verifier and real cycles are
required before #45 can close.

## Scope and command

`scripts/demo_signal_capture.mjs` queries only the public gateway routes:
two Prometheus expressions and two Lucene OpenSearch queries from the pinned
[demo signal definitions](../demo-signals.md). It emits bounded counts,
source/window and settlement timestamps, never raw log bodies, trace IDs,
headers or tokens. After each `fail`/`reset`, the operator must supply the
transition time and wait at least 150 seconds before capture.

The controlled E2E uses an in-container loopback gateway fixture with the
real HTTP/CLI process, including a private marker in upstream-shaped bodies.
This local Docker daemon could not allocate another Compose network; a cached
Node 22.14 harness image ran the test with `--network none` and read-only
script/test/schema mounts. Reproduction on a host with network capacity:

```sh
docker compose --env-file .env --env-file .env.worktree -p issue45-signal-checks --profile checks run --build --rm --no-deps -v "$PWD/tests:/source/tests:ro" harness node --test /source/tests/test_demo_signal_capture.mjs
```

The host needs Git, Docker, a safe untracked `.env` from `.env.example`, and
`.env.worktree` generated by `scripts/bootstrap-worktree.py`. No provider
credential, demo, PostgreSQL or outbound network is required by this test.

## Observed behavior

- Test-first RED: 0/1 passed because the CLI file did not exist. The test
  exercised a process-level HTTP client and loopback server, not an imported
  implementation function.
- GREEN: 1/1 passed, Node v22.14.0, no skips. Across baseline and failure,
  exactly eight authorized POSTs were observed; no alternate route or token
  appeared in output. The baseline reported checkout errors/stalled orders
  `0/0`; the failure reported `12/3`, with three proxy 500s. The one-result
  shape, datasource UIDs, two-minute window and Lucene syntax were checked.
- A capture requested only 20 seconds after transition failed with
  `signal_window_not_settled` **before contacting the gateway**.
- Synthetic upstream marker, bearer token and private trace IDs were absent
  from both serialized capture reports.

The runner does not change demo state and does not infer recovery from a healthy
service. CA8 remains pending until six real baseline/failure/reset reports
from two cycles pass a separate chronological verifier on the integrated
current-main runtime.
